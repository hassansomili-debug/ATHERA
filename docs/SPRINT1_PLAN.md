## 2. الخطة المعمارية

```
رفع ملف (Sprint 0)
   ↓
Parser            → نص + locator لكل مقطع (صفحة/قسم/فقرة)
   ↓
document_chunks   → تقطيع بنيوي، كل مقطع موسوم untrusted
   ↓
Extractor         → مرشّح حقيقة + اقتباس حرفي + مرجع المقطع
   ↓  ⟵ حاجز مضاد للاختلاق: الاقتباس يجب أن يوجد حرفيًا في المقطع، وإلا رُفض المرشّح آليًا
fact_candidates   → status = unverified دائمًا. لا استثناء.
   ↓  ⟵ بوابة G0: قرار إنسان
researcher_memories → ذاكرة موثقة + provenance + audit
```

**قراران يستحقان التسجيل:**

1. **المستخرِج قابل للتبديل، والافتراضي حتمي.** `RuleBasedExtractor` يعمل بلا نموذج إطلاقًا (ORCID، الرتب، البرمجيات، المناهج). `ModelExtractor` يمر عبر بوابة §32 حين يُفعَّل مزود. هذا يجعل خط الأنابيب كاملًا وقابلًا للاختبار مع `MODEL_PROVIDER=null`، ويمنع ارتهان الأساس بمزود.

2. **الاقتباس الحرفي شرط قبول لا حقل عرض.** كل مرشّح يحمل `quote`، ويُتحقق آليًا من وجوده حرفيًا داخل نص المقطع المرجعي. مرشّح بلا اقتباس مطابق يُرفض قبل أن يصل إلى قائمة المراجعة. هكذا يصبح مبدأ **No Fabrication** (§4) خاصية تنفيذية لا وعدًا.

**البحث النصي بالعربية:** PostgreSQL لا يحمل قاموس تجذير عربيًا. نستخدم `to_tsvector('simple', …)` + `pg_trgm`، والاسترجاع الدلالي يتكفل بالباقي حين يتوفر مزود embeddings. لا ندّعي تجذيرًا عربيًا غير موجود.

## 3. تغييرات Schema و API

**جداول جديدة (ترحيل 0005):** `researcher_profiles` · `researcher_skills` · `researcher_memories` · `document_chunks` (بعمود `vector(1536)` قابل للإفراغ) · `extraction_runs` · `fact_candidates`

**قيود مفروضة في قاعدة البيانات:**
- `researcher_memories.verification_status = 'verified'` يستلزم `verified_by` و`verified_at` و`source_type` من المسارات الأربعة في §7.4.
- `fact_candidates` يبدأ دائمًا `unverified`؛ لا قيمة افتراضية أخرى.
- `document_chunks.locator` إلزامي — مقطع بلا موضع لا يصلح مصدرًا.

**نقاط API:**
```
POST   /api/v1/profile/import            # ملف → تفكيك → استخراج → قائمة مراجعة
GET    /api/v1/profile
PATCH  /api/v1/profile
GET    /api/v1/profile/facts             # قائمة المراجعة
POST   /api/v1/profile/facts/{id}/approve
POST   /api/v1/profile/facts/{id}/reject
GET    /api/v1/memory                    # الذاكرة الموثقة + بحث هجين
```

## 4. الأمن والخصوصية

| المخاطرة | الضابط |
|---|---|
| حقن أوامر عبر PDF (§33.3) | المقاطع `is_untrusted=true`؛ المستخرِج الحتمي لا يقرأ تعليمات أصلًا؛ واختبار يثبت أن نصًا آمرًا داخل مستند لا يرفع حالة أي حقيقة |
| تسريب محتوى حساس لمزود | `ModelExtractor` يرث سقف التصنيف من `files.classification` عبر بوابة §32 |
| ترقية صامتة إلى «موثق» | قيد قاعدة بيانات + خدمة `memory.promote` هي المسار الوحيد، وتكتب provenance وaudit في المعاملة نفسها |
| تضخم التخزين | حد على عدد المقاطع لكل ملف، ونص المقطع مقتطع بحد أقصى |

## 6. افتراض مفتوح

**تشفير نص المقاطع في قاعدة البيانات.** المقاطع تحمل نص رسائل وسير ذاتية (C2). تشفيرها على مستوى العمود يحتاج KMS، وKMS ينتظر قرار Hosting region. أعمل الآن بتشفير القرص فقط، وأسجّلها امتدادًا للمخاطرة المعلنة رقم 2 في نموذج التهديد.

## 7. ما تغيّر أثناء التنفيذ

خطآن وُجدا بتشغيل الكود فعليًا — لا بمراجعته — وأُصلحا مع اختبارَي انحدار:

1. **واو العطف الملتصقة بمصطلح لاتيني.** `\b` لا يرى حدًّا بين «و» و«S» في «وSmartPLS» لأن كليهما حرف كلمة في Unicode. هذه صيغة كتابة عادية في السير الذاتية العربية، وكانت تُسقط نصف المهارات بصمت. الحل: حدود مبنية على نفي الحروف اللاتينية والشرطة بدل `\b`. أزال هذا أيضًا التقاط «SEM» من داخل «PLS-SEM».

2. **العناوين العربية غير المدرجة في قائمة الكلمات.** «السيرة الذاتية» و«المهارات» كانت تُسقط لقصرها، فيفقد كل مقطع سياق قسمه. الحل: قاعدة بنيوية — سطر قصير، وحده في فقرته، بلا علامة نهاية جملة — إلى جانب القائمة المسمّاة.

الدرس المسجَّل: أي اعتماد على `\b` أو على قوائم كلمات مغلقة في نص عربي يحتاج اختبارًا بنص عربي حقيقي، لا بمراجعة بصرية.
