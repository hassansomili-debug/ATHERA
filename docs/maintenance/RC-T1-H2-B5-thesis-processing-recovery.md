# RC-T1-H2-B5 — استئنافُ معالجةِ الرسالة، وسياجُ عاملِها

## العطب

مهامُّ `BackgroundTasks` تعيش **داخل عملية الـAPI**. فإعادةُ نشرٍ أو سقوطُ
آلةٍ أثناء العمل تترك الصفَّ عند `queued` أو `parsing` أو `extracting`، ولا
يستأنفه أحد. و`claim_for_processing` كان يرفض كلَّ حالٍ جاريةٍ **إلى الأبد**،
فلا طلبَ جديدٌ يُقبل عليها: الرسالةُ تعلق، والبطاقةُ تقول «جارٍ» ولا شيء يجري.

## ما هو مُغلَق الآن — وبأيّ لفظ

```
Lost/interrupted in-process thesis task                  : RECOVERABLE — by an
                                                           authorized later request
Stale worker writing after takeover                      : CLOSED — DB fence
Duplicate logical extraction within one attempt          : CLOSED — stable run id
Blind model re-invocation inside one processing attempt  : CLOSED — section ledger
Two theses for one file                                  : CLOSED — file row lock
Durable queue                                            : NOT CLAIMED
Automatic crash recovery                                 : NOT CLAIMED
BackgroundTasks surviving process death                  : NOT CLAIMED — it does not
Exactly-once processing                                  : NOT CLAIMED
Exactly-once model execution                             : NOT CLAIMED
RC-T1-H2 globally                                        : NOT CLOSED
Web Idempotency-Key adoption                             : OPEN — later work
```

**والدعوى المأذونة حرفيًّا:**

> مهمّةٌ ضاعت أو انقطعت يمكن استئنافُها بطلبٍ مأذونٍ لاحق، بلا تكرارِ
> الاستخراجِ المنطقيّ، وبلا أن يكتب عاملٌ بائتٌ بعد الاستعادة، وبلا نداءٍ
> أعمى لمزوّدٍ غيرِ مُثبَتِ المنعة داخل جيلِ المعالجةِ نفسِه.

ويجوز أيضًا: **إعادةُ معالجةٍ مقصودةٌ جديدةٌ جيلٌ آخر، ويجوز فيها نداءُ
النموذجِ مجدّدًا.**

## لا طابورَ دائمًا — وهذا يُقال لا يُخفى

`BackgroundTasks` ليست طابورًا دائمًا، ولا تنجو من موتِ العمليّة. ولم يُدخَل
Temporal ولا Celery ولا RQ ولا Kafka ولا قفلُ Redis لأجل هذا الطور.
**الاستئنافُ صريحٌ ومنسَّقٌ بالقاعدة**: لا يقع من تلقائه، بل يطلبه مستخدمٌ
مأذونٌ — أو تطلبه إعادةُ طلبٍ مُمفتَحٍ تكتشف أنّ الجدولةَ ضاعت.

## الطبقاتُ الثلاث — ولا تُخلط

| الطبقة | ما تمنعه | عمرُها |
|---|---|---|
| `Idempotency-Key` في HTTP | طفرةَ طلبٍ مكرّرة | الطلب |
| محاولةُ المعالجة (`processing_attempts`) | استخراجًا منطقيًّا مكرّرًا | تعيش بعد الجواب |
| جيلُ القسم الداخليّ | نداءً مدفوعًا مكرّرًا | داخل المحاولة |

**وجوابُ ٢٠٢ مخزونٌ لا يُثبت أنّ العاملَ عمل.** ومعرّفُ المحاولةِ وحده لا
يُثبت أنّ قسمًا لم يُنفَّذ.

## السياج

`processing_state_changed_at` هو السياج **وهو الطابعُ الصادقُ للمستعمل معًا**.
يُكتب بساعة القاعدة (`func.now()`) لا بساعة العملية، ويتقدّم مع كلِّ انتقالٍ
حقيقيّ — فهو النبضُ نفسُه لا مؤقّتٌ يعمل على حدة. وعاملٌ قديمٌ يحمل طابعًا
بائتًا لا يصيب صفًّا، ويرفع `ProcessingSuperseded` فتُرجَع معاملتُه كلُّها.

وعتبةُ الهجران **مشتقّةٌ من زمنِ العملِ لا رقمٌ يُختار**: جلبُ التخزين
(`LEASE_STORAGE`) وسبعةُ أقسامٍ كلٌّ بـ`LEASE_MODEL` وهامش — أربعون دقيقة،
تُحسَب من الثوابت فلا تنفصل عنها.

## أفقُ السِّجلّ

سِجلُّ تنفيذِ الأقسام له بقاءٌ منطقيٌّ (٢٤ ساعة). ومحاولةٌ تُستعاد بعده تجد
مفاتيحَ أقسامها كأنّها جديدة — فيُنادى المزوّدُ على أقسامٍ ربّما نُفِّذت.
فالاستعادةُ لا تتجاوز الأفق: بعده تبدأ **محاولةٌ جديدةٌ مقصودة**، ومرساةُ
العمرِ `ExtractionRun.started_at` لا الطابعُ المتجدّد.

## الفاعلُ التقنيُّ الثابت

`idempotency_records` محكومةٌ بـRLS على المستأجرِ **والفاعل**. والاستعادةُ قد
يطلبها مستخدمٌ آخرُ مأذون — فلو نُسب جيلُ القسم إلى «من ضغط الاستعادة» لصار
لكلٍّ جيلُه فيُنادى المزوّدُ مرّةً لكلِّ مستعيد.

فيُنسَب إلى `File.uploaded_by`: عمودٌ غيرُ فارغٍ ودائم. **وهو سياقُ RLS
وحدَه — لا تفويضٌ، ولا إثباتُ وصولٍ حاليّ، ولا يُكتب فاعلًا في التدقيق.**
وفُحص أنّ `idempotency_records` وحدها محكومةٌ بالفاعل في هذا الخطّ؛ وما عداها
بالمستأجر، فضبطُ السياق على الرافع لا يغيّر ما يراه العامل.
