# ADR-0003 — Model Provider Gateway واستقلال المزوّد

- **الحالة:** مقترح (بانتظار الاعتماد)
- **التاريخ:** 2026-08-30
- **المرجع:** §32، §4 (Provider Independent، Backend-mediated AI)، §38.6.3، §38.6.8، §36.3

## السياق
تنص المبادئ غير القابلة للتفاوض على أمرين: ألا تُربط المنصة بمزود نموذج واحد، وأن يُمنع الاتصال المباشر بين واجهة المستخدم ومزود النموذج. الالتزام الثاني ليس تفضيلًا أسلوبيًا: تمرير كل استدعاء عبر الخادم هو ما يجعل الصلاحيات والذاكرة الموثقة وحماية البيانات وضبط التكلفة وسجل التدقيق ممكنة أصلًا.

## القرار
1. واجهة واحدة `ModelProvider` بأربع عمليات: `generate_structured` · `embed` · `stream` · `tool_call`.
2. **لا تظهر أنواع أو حمولات خاصة بمزود بعينه في طبقة الـdomain** — التحويل يقع كله داخل الـadapter.
3. Sprint 0 يسلّم: الواجهة، `OpenAIAdapter`، و`NullProvider` حتمي للاختبارات.
4. كل استدعاء يُسجَّل في `model_runs`: المزود، النموذج، الرموز المستهلكة، التكلفة، الـlatency، النتيجة، ومعرّف يُشار إليه من `model_run_id` في الحقول المعرفية (§29.2).
5. اختيار النموذج حسب المهمة يقع في طبقة السياسات لا في كود الميزة.
6. مفتاح على مستوى المستأجر يمنع إرسال فئات بيانات محددة إلى مزود خارجي (§36.3)، وقيمته الافتراضية **الأشد تقييدًا**.
7. **الفرض التقني لا التوثيقي:** `import-linter` يمنع استيراد أي SDK مزود خارج `api/providers/`؛ واختبار يفشل إذا احتوت حزمة الواجهة على SDK أو مفتاح؛ وCSP تحظر `connect-src` نحو نطاقات المزودين.

## البدائل المرفوضة
- **استدعاء المزود من المتصفح مباشرة:** يكسر §38.6.8 ويجعل التدقيق والصلاحيات وضبط التكلفة مستحيلة. مرفوض قطعًا.
- **استخدام SDK المزود مباشرة في كود الميزات مع نية التجريد لاحقًا:** التجريد المؤجل لا يحدث؛ الحمولات الخاصة بالمزود تتسرب إلى الـdomain خلال أسابيع.
- **طبقة تجريد خارجية جاهزة (LiteLLM ونحوها):** خيار معقول، لكنه يضيف تبعية تتحكم في نقطة حرجة قبل استقرار المتطلبات؛ يمكن اعتماده لاحقًا **خلف** نفس الواجهة دون تغيير الـdomain.

## النتائج
- **إيجابًا:** تبديل المزود يصبح تغييرًا في طبقة واحدة؛ الاختبارات حتمية عبر `NullProvider`؛ التكلفة مرصودة منذ اليوم الأول.
- **سلبًا:** الميزات الخاصة بمزود واحد لا تُستخدم إلا عبر توسيع الواجهة صراحةً — احتكاك مقصود.
