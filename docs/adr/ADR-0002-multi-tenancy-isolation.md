# ADR-0002 — نموذج العزل بين المستأجرين

- **الحالة:** مقترح (بانتظار الاعتماد) — **قرار حاسم يشكّل كل جدول واستعلام**
- **التاريخ:** 2026-08-30
- **المرجع:** §36.1 (Tenant isolation)، §38.3 (Multi-tenant from architecture level)، §46 (Private tenant / Optional private deployment)، §50 (تثبيت نموذج الـMulti-tenancy)

## السياق
تحمل المنصة بيانات بالغة الحساسية: ملفات باحثين، رسائل علمية غير منشورة، بيانات مشاركين، ولوائح ترقية مؤسسية. تسرّب بين مستأجرين ليس عيبًا وظيفيًا بل حدث فقدان ثقة نهائي. في الوقت نفسه، يستهدف الإصدار الأول باحثًا واحدًا ثم فرقًا صغيرة، ولا يحتمل كلفة تشغيل قاعدة بيانات لكل عميل.

## القرار
**قاعدة بيانات وschema مشتركة، مع `tenant_id` على كل جدول، وRow-Level Security إجبارية في PostgreSQL.**

1. كل جدول يحمل `tenant_id UUID NOT NULL`، وعليه `ENABLE ROW LEVEL SECURITY` و`FORCE ROW LEVEL SECURITY`.
2. سياسة موحّدة: `USING (tenant_id = current_setting('app.tenant_id')::uuid)`.
3. دور قاعدة البيانات الذي يستخدمه التطبيق **لا يملك `BYPASSRLS`** وليس مالك الجداول.
4. كل طلب يفتح transaction ويضبط `SET LOCAL app.tenant_id` بعد المصادقة مباشرة، قبل أي استعلام.
5. Object Storage: بادئة `tenants/{tenant_id}/` وسياسة تمنع الوصول العابر.
6. اختبار CI يمر على `information_schema` ويفشل البناء عند وجود أي جدول بلا RLS مفعّلة.

**مسار الترقية:** عميل مؤسسي يطلب عزلًا فعليًا (§46) يُنقل إلى قاعدة بيانات مستقلة بنفس الـschema ونفس كود التطبيق — العزل يتغير في طبقة الاتصال لا في المنطق.

## البدائل المرفوضة
- **schema لكل مستأجر:** عزل أوضح، لكن الترحيلات تصبح N عملية وتتدهور مع النمو، وأدوات الترحيل تتعقد بلا مقابل في هذه المرحلة.
- **قاعدة بيانات لكل مستأجر من البداية:** أقوى عزلًا وأثقل تشغيلًا بكثير قبل وجود عميل مؤسسي واحد. مؤجل كمسار ترقية لا كنقطة بداية.
- **الاعتماد على فلترة `WHERE tenant_id` في الكود فقط:** سطر منسي واحد يساوي تسريبًا. **مرفوض قطعًا** — العزل يجب أن يكون خاصية قاعدة بيانات لا انضباط مطوّرين.

## النتائج
- **إيجابًا:** خطأ برمجي عادي لا يكفي وحده لتسريب بيانات؛ ترحيل واحد يخدم كل المستأجرين.
- **سلبًا:** كل مسار كتابة يعتمد على ضبط `app.tenant_id` — نسيانه يعني صفرًا من النتائج (فشل آمن)، وهو السلوك المطلوب. يُختبر بـAT-S0-01.
- عبء أداء طفيف على المخطِّط، يُعالج بفهارس مركّبة تبدأ بـ`tenant_id`.
